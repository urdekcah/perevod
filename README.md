# perevod

**Перевод с русского на корейский. Локально, на Apple Silicon.**

[![code](https://img.shields.io/badge/code-AGPL--3.0--only-0b7285)](LICENSE)
[![data](https://img.shields.io/badge/data-CC%20BY--NC--SA%204.0%20RU-ae3ec9)](data/LICENSE)
[![python](https://img.shields.io/badge/python-3.12%2B-306998)](pyproject.toml)
[![platform](https://img.shields.io/badge/platform-Apple%20Silicon-1c1c1e)](#требования)

Сеть не нужна: модель лежит на диске, считает GPU. Терминал и Python работают через один
движок.

```sh
perevod translate "Здравствуйте, как дела?"
# 안녕하세요, 어떻게 지내세요?
```

---

## Требования

| Что нужно | Почему |
|---|---|
| Mac на Apple Silicon, M1 и новее | MLX считает только на этих чипах |
| macOS 15.0 или новее | Практический минимум для MLX |
| Python 3.12 или новее | Нижняя граница из `pyproject.toml` |
| 5 ГБ на диске, сеть — однократно | Столько весит модель; дальше она берётся из кеша |

## Установка

```sh
pip install -e .
```

Ставятся четыре пакета: `mlx`, `mlx-lm`, `transformers`, `click`. Лицензии — в `NOTICE.md`.

## Перевод

```sh
perevod translate "Здравствуйте, как дела?"
cat письмо.txt | perevod translate -
```

Без аргумента или с `-` команда читает стандартный ввод и возвращает только перевод — её можно
ставить в конвейер.

| Флаг | Назначение |
|---|---|
| `--model` | Другой репозиторий модели |
| `--adapter-path` | Адаптер поверх базовой модели |
| `--allow-provenance-mismatch` | Допустить адаптер от другой базы или формы запроса |
| `--max-tokens` | Потолок ответа, по умолчанию `512`. Упёрлись в него — ошибка, а не укороченный перевод. Заданный явно, распространяется и на каждый кусок файла, отменяя автоподбор |

### Файлы

С `--input` текст делится на куски по абзацам, каждый переводится отдельно, документ
собирается обратно: пустые строки встают ровно туда, где стояли.

```sh
perevod translate --input письмо.txt --output письмо.ko.txt
perevod translate --input а.txt --input б.txt --output-dir переводы/
```

Без `--output` и `--output-dir` перевод уходит в стандартный вывод, ход работы — в поток
ошибок.

| Флаг | Назначение |
|---|---|
| `--input` | Исходник из файла; допускает повтор |
| `--output` | Файл назначения; требует ровно один `--input` |
| `--output-dir` | По файлу на каждый вход; обязателен от двух входов |
| `--force` | Разрешить перезапись файла назначения |
| `--encoding` | Кодировка входа, по умолчанию `utf-8-sig` |
| `--chunk-budget` | Размер куска в токенах, по умолчанию `1024` |
| `--progress` / `--no-progress` | Ход работы в поток ошибок; включён для терминала |

Имя выходного файла образуется вставкой `.ko` перед последним расширением: `doc.txt` →
`doc.ko.txt`, `doc` → `doc.ko`, `a.tar.gz` → `a.tar.ko.gz`. Модель загружается однократно
на весь запуск; пакетный режим последователен, а не параллелен.

**Кодировки.** Вход читается как `utf-8-sig`, метка порядка байтов в запрос не попадает.
Нечитаемый файл останавливает команду с указанием флага: подменять байты и выдавать
правдоподобную кашу она не станет. `\r\n` и `\r` приводятся к `\n`, выход всегда UTF-8
с `\n`. Формат — простой текст; `.md` тоже уедет в модель обычными абзацами.

**Несостоявшийся кусок** оставляет по себе пометку с исходником внутри, а не пустоту, которую
можно принять за перевод:

```text
[[PEREVOD:UNTRANSLATED chunk=47]]
Исходный русский текст этого куска.
[[/PEREVOD:UNTRANSLATED chunk=47]]
```

Три неудачи подряд считаются системным сбоем: запуск прекращается, остальные куски получают
ту же пометку без обращения к модели.

Готовые куски копятся в соседнем `<файл>.part` и занимают место назначения лишь в конце, так
что наполовину записанного файла не бывает, а после `Ctrl-C` работа уцелеет. Выходной путь
сверяется до загрузки модели: запись поверх исходника, поверх существующего файла без `--force`
и пакет, где два входа дают одно имя, отклоняются.

| Код возврата | Значение |
|---|---|
| `0` | Переведены все куски всех файлов |
| `1` | Перевод получен, но часть кусков или файлов не далась |
| `2` | Ошибка в аргументах или отклонённый путь; не записано ничего |

### Из Python

```python
from perevod import Translator

translator = Translator()
print(translator.translate("Здравствуйте, как дела?"))
```

При создании `Translator` забирает веса в память — несколько гигабайт. Заведите один экземпляр:
собирать новый на каждую фразу расточительно.

## Подготовка данных

Пары пишутся вручную в `data/derived/` файлами `*.txt` — по паре на строку, стороны через
`|||`. Формат описан в `data/README.md`.

```sh
perevod prepare-data
```

Команда читает `data/derived/`, выверяет корпус целиком до первой записи, отбрасывает
дубликаты и раскладывает остаток на `train.jsonl`, `valid.jsonl`, `test.jsonl`
и `manifest.json` в `data/splits/` — имена, которых ждёт `mlx_lm.lora`.

| Флаг | Назначение |
|---|---|
| `--output-dir` | Куда писать, по умолчанию `data/splits/` |
| `--seed` | Зерно раскладки, по умолчанию `0` |
| `--valid-fraction`, `--test-fraction` | Доли проверки и теста, по умолчанию `0.1` |
| `--max-length-ratio` | Предел расхождения длин; `0` снимает проверку |
| `--allow-source-conflicts` | Допустить один исходник с разными переводами |
| `--overwrite` | Заменить свои файлы в непустом каталоге |

```python
from perevod import PrepareConfig, prepare_splits

result = prepare_splits(PrepareConfig(seed=0))
print(result.manifest["counts"])
```

Отсюда три гарантии: ошибочная строка называется по файлу и номеру прежде любой записи; то же
зерно даёт побайтово те же выборки; ни одно предложение не попадает разом в обучение и в тест.
Непустой `data/splits/` не затирается — на этих выборках мог быть обучен адаптер.

## Дообучение

```sh
perevod train
perevod validate-data   # выверить данные, не запуская обучение
```

LoRA-адаптер обучается на выборках из `data/splits/` и попадает в `data/adapters/current/`.
Обязателен `train.jsonl`; без `valid.jsonl` ошибка на проверочной части не считается, о чём
команда предупредит.

| Флаг | Назначение |
|---|---|
| `--data` | Каталог выборок, по умолчанию `data/splits/` |
| `--model` | Какую модель дообучать |
| `--adapter-path` | Куда положить адаптер, по умолчанию `data/adapters/<run-name>` |
| `--run-name` | Имя запуска в пути по умолчанию, по умолчанию `current` |
| `--iters` | Число шагов |
| `--batch-size` | Размер минибатча |
| `--learning-rate` | Скорость обучения |
| `--num-layers` | Сколько слоёв дообучать; `-1` — все |
| `--max-seq-length` | Потолок длины последовательности |
| `--seed` | Зерно генератора |
| `--mask-prompt` | Считать ошибку только по корейской стороне |
| `--grad-checkpoint` | Обменять скорость на память |
| `--overwrite` | Заменить адаптер в непустом каталоге |

Незаданный флаг не передаётся вовсе: в силе остаётся значение самого `mlx_lm.lora`, а не наша
догадка о нём. Ранг LoRA задаётся только из YAML-конфигурации — флагом закреплённая версия его
не принимает.

```python
from perevod import TrainingConfig, train_adapter

adapter_path, report = train_adapter(TrainingConfig(iterations=200, batch_size=1))
```

Выборки прочитываются целиком до старта, и несовпадение формы запроса или неразбираемая строка
останавливают запуск — иначе о расхождении стало бы известно часом позже. Непустой каталог
адаптера не затирается.

Адаптер привязан к форме запроса, на которой обучался: правка `build_messages` или текста
инструкции делает все прежние адаптеры непригодными, и починить их нельзя — только переобучить.

### Если не хватает памяти

Модель закреплена в 4 битах, поэтому обучение и так идёт как QLoRA. Базовые веса заморожены,
учатся только матрицы адаптера: постоянная часть расхода примерно равна той же модели
на переводе, переменная растёт от длины последовательности и размера батча. Ослабляйте
по порядку: `--batch-size`, `--num-layers`, `--grad-checkpoint`, затем короткие пары вместо
длинных.

Расход на полном корпусе не измерялся. Измерено: восемь коротких пар,
`--batch-size 1 --num-layers 4 --iters 4` — 14,7 с, 5,0 ГБ максимального резидентного размера,
44 токена в секунду. Цифра говорит о постоянной части расхода и почти ничего — о переменной.
Внешняя точка: Mistral-7B на M1 Max с 32 ГБ при тех же флагах даёт около 250 токенов
в секунду. Полный выигрыш от нейроускорителей M5 требует macOS 26.2 или новее.

## Перевод с адаптером

Адаптер подкладывается поверх базы на лету: база остаётся замороженной и четырёхбитной, ничего
не сливается. Это основной путь.

```sh
perevod translate --adapter-path data/adapters/current "Здравствуйте, как дела?"
PEREVOD_ADAPTER=data/adapters/current perevod translate "Здравствуйте, как дела?"
```

```python
translator = Translator(adapter_path="data/adapters/current")
```

Побеждает то, что выше: аргумент, за ним `PEREVOD_ADAPTER`, за ней — никакого адаптера.
По умолчанию адаптер не подставляется: его выбирают осознанно.

### Происхождение

Адаптер от одной базы, подложенный под другую, не падает — он молча переводит хуже. Поэтому
`perevod train` кладёт рядом `perevod_provenance.json`: база, форма запроса, дата, версия
обучателя.

| Что в каталоге адаптера | Что произойдёт |
|---|---|
| Файла нет | Предупреждение в `stderr`, перевод продолжится |
| База и форма совпали | Перевод пойдёт молча |
| База другая | Ошибка до загрузки модели |
| Форма запроса другая | Ошибка до загрузки модели |
| Файл повреждён | Ошибка; флагом не снимается |

`--allow-provenance-mismatch` смягчает две ошибки о несовпадении до предупреждений.
Повреждённый файл им не снимается: принимать там нечего. Копируете адаптер — копируйте файл
вместе с ним, иначе получатель обойдётся предупреждением вместо проверки.

### Слияние с базой

`mlx_lm.fuse` вплавляет адаптер в веса и отдаёт обычный каталог модели. Это удобство
для выгрузки, а не рабочий путь.

**Слияние может потерять выученное поведение.** Открытая проблема
[`ml-explore/mlx-lm#654`](https://github.com/ml-explore/mlx-lm/issues/654) описывает ровно это,
причём на дообучении русским. Обёртки вокруг `mlx_lm.fuse` в проекте нет намеренно.

По умолчанию `mlx_lm.fuse` читает из `adapters/` и пишет в `fused_model/` относительно текущего
каталога — то есть в корень репозитория, мимо `data/`. Пути задавайте явно:

```sh
mlx_lm.fuse \
  --model mlx-community/gemma-4-e4b-it-4bit \
  --adapter-path data/adapters/current \
  --save-path ~/models/perevod-fused

perevod translate --model ~/models/perevod-fused "Здравствуйте, как дела?"
```

Прежде чем отдавать такой каталог, сличите на `perevod.probes.PROBE_SENTENCES` три прогона:
голая база, база с адаптером, слитая модель. Если база и адаптер не разошлись хотя бы
на половине набора, сравнение ничего не докажет. Слитая модель, сбивающаяся на русский или
латиницу там, где адаптер давал корейский, распространению не подлежит.

## Оценка качества

`evaluate` прогоняет по одной отложенной выборке голую базу и базу с адаптером и сличает их
одной метрикой:

```sh
perevod evaluate --adapter-path data/adapters/current --limit 20
```

```python
from perevod import EvaluationConfig, evaluate_pair, render_summary, write_run

run = evaluate_pair(EvaluationConfig(adapter_path="data/adapters/current"))
write_run(run)
print(render_summary(run))
```

Начинайте с `--limit`: это первые N строк в порядке файла, дешёвая проверка проходимости пути.
Обе поверхности идут одним кодом и дают одну запись прогона в `data/eval/`.

**Почему chrF, а не BLEU.** BLEU требует бесспорного разбиения на слова, а в корейском его нет:
эоджоль несёт основу вместе с частицами, и расхождение в одну частицу стоит целого токена —
столько же, сколько утраченное знаменательное слово. Пробелы между эоджолями вдобавок плавают.
chrF считает по символьным n-граммам и засчитывает частичное совпадение внутри эоджоля — там,
где корейский и несёт морфологию. Именно chrF, а не chrF++: `WORD_ORDER = 0`, иначе словесные
n-граммы вернули бы ту самую чувствительность к токенизации. BLEU не считается вовсе: без имени
токенизатора это число ничего не значит, а взять имя неоткуда.

**Что число означает.** Единственная законная точка отсчёта — та же база на той же выборке
с теми же настройками генерации; ради этого базовая ветка и существует. Опубликованные
Helsinki-NLP `BLEU 30.3 / chrF 0.514` — контекст, а не цель: другое направление (`ko→ru`),
другая модель, другой набор (221 предложение Tatoeba), другая шкала (`0.514` и `51.4` — одно
число). Метрика здесь своя, с эталонной реализацией не сверялась: **числа сопоставимы только
между собой**, публиковать их как chrF нельзя. Рядом с каждым числом идёт `n`; число без `n`
не значит ничего.

Порог, ниже которого улучшение не объявляется, — максимум из трёх величин: разброс между
повторными прогонами, оценка бутстрапом (`--bootstrap-seed`) и `MIN_REPORTABLE_DELTA_CHRF = 1.0`.
Последнее — соглашение проекта, а не порог статистической значимости.

**Когда сравнение отклоняется:** тест пересекается с `train.jsonl` или `valid.jsonl` (мерилось бы
запоминание — пересоберите выборки); адаптер обучался на другой базе (ветки разошлись бы
не только адаптером; с `--allow-provenance-mismatch` прогон пройдёт, но вердикт будет
`unavailable`); ветки дали почти одинаковый текст (вердикт `indistinguishable` — он не выбирает
между «адаптер недоучен» и «адаптер не применился»).

Вердикт — всегда одно из `improved`, `regressed`, `indistinguishable`, `unavailable`. Читать
надо его, а не дельту.

## Выбор модели

```sh
perevod translate --model mlx-community/gemma-4-31b-it-4bit "Добрый день"
PEREVOD_MODEL=mlx-community/gemma-4-31b-it-4bit perevod translate "Добрый день"
```

По умолчанию берётся `mlx-community/gemma-4-e4b-it-4bit`. Побеждает то, что выше: `--model`,
за ним `PEREVOD_MODEL`, за ней значение по умолчанию. Пустая переменная считается незаданной.

## Как устроено

Запрос к модели — диалог из двух реплик: системная ставит задачу, пользовательская несёт
исходный текст. Обе собирает `build_messages`, единственное описание формы запроса; на неё
опирается и дообучение, поэтому менять форму в одиночку нельзя.

Загрузку модели и генерацию `Translator` принимает аргументами конструктора, поэтому
с подставными функциями весь путь перевода проверяется там, где MLX не установлен. Адаптер
он берёт тем же конструктором, вместе с базой: пути, на котором адаптер попал бы в модель
в обход базы, в коде нет.
