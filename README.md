# perevod

[![license](https://img.shields.io/badge/license-AGPL--3.0--only-0b7285)](LICENSE)
[![python](https://img.shields.io/badge/python-3.12%2B-306998)](pyproject.toml)
[![platform](https://img.shields.io/badge/platform-Apple%20Silicon-1c1c1e)](#требования)

**Русско-корейский перевод, который не ходит в сеть.** Модель лежит на диске, вычисления идут
на GPU вашего Mac. За двумя интерфейсами — командой в терминале и классом в Python — работает
один движок.

```sh
perevod translate "Здравствуйте, как дела?"
# 안녕하세요, 어떻게 지내세요?
```

---

## Требования

| Что нужно | Откуда требование |
|---|---|
| Mac на Apple Silicon, M1 и новее | Движок построен на MLX, а тот считает только на этих чипах |
| macOS 15.0 или новее | Практический минимум для MLX |
| Python 3.12 или новее | Нижняя граница из `pyproject.toml` |
| Около 5 ГБ на диске и сеть один раз | Столько весит модель; дальше она берётся из кеша |

## Установка

```sh
pip install -e .
```

## Как пользоваться

### Из терминала

```sh
perevod translate "Здравствуйте, как дела?"
```

Без аргумента или с `-` команда читает стандартный ввод и отдаёт только перевод, поэтому её
можно ставить в конвейер:

```sh
cat письмо.txt | perevod translate -
```

| Флаг | Что делает |
|---|---|
| `--model` | Берёт другой репозиторий модели |
| `--max-tokens` | Потолок длины ответа. По умолчанию `512` |

### Из Python

```python
from perevod import Translator

translator = Translator()
print(translator.translate("Здравствуйте, как дела?"))
```

`Translator` забирает веса в память при создании — несколько гигабайт. Заведите один экземпляр
и работайте с ним: собирать новый на каждую фразу дорого.

## Подготовка данных к дообучению

Пары вы пишете вручную и складываете в `data/derived/` файлами `*.txt` — по паре на строку,
стороны через `|||`. Формат описан в `data/README.md`.

```sh
perevod prepare-data
```

Команда читает `data/derived/`, проверяет корпус целиком и до первой записи, отбрасывает
дубликаты и раскладывает остаток на `train.jsonl`, `valid.jsonl`, `test.jsonl`
и `manifest.json` в `data/splits/` — те самые имена, которых ждёт `mlx_lm.lora`.

| Флаг | Что делает |
|---|---|
| `--output-dir` | Куда писать. По умолчанию `data/splits/` |
| `--seed` | Фиксирует раскладку. По умолчанию `0` |
| `--valid-fraction`, `--test-fraction` | Доли под проверку и тест. По умолчанию `0.1` |
| `--max-length-ratio` | Граница расхождения длин; `0` снимает проверку |
| `--allow-source-conflicts` | Разрешить один исходник с разными переводами |
| `--overwrite` | Заменить свои файлы в непустом каталоге |

То же самое из Python — та же реализация, не вторая:

```python
from perevod import PrepareConfig, prepare_splits

result = prepare_splits(PrepareConfig(seed=0))
print(result.manifest["counts"])
```

Ради трёх гарантий команда и написана: ошибочная строка называется по файлу и номеру ещё
до того, как что-то записано; тот же ввод с тем же зерном даёт побайтово те же выборки;
ни одно предложение не попадает разом в обучение и в тест. Непустой `data/splits/` команда
не затирает — на этих выборках мог быть обучен адаптер.

## Выбор модели

По умолчанию берётся `mlx-community/gemma-4-e4b-it-4bit`. Сменить модель можно,
не притрагиваясь к коду:

```sh
perevod translate --model mlx-community/gemma-4-31b-it-4bit "Добрый день"
PEREVOD_MODEL=mlx-community/gemma-4-31b-it-4bit perevod translate "Добрый день"
```

Побеждает то, что выше: флаг `--model`, за ним переменная `PEREVOD_MODEL`, за ней значение
по умолчанию. Пустую переменную движок считает незаданной.

## Как устроено

Запрос к модели — диалог из двух реплик: системная ставит задачу, пользовательская несёт
исходный текст. Обе собирает `build_messages` — единственное место, где описана форма запроса.
На неё опирается и дообучение, поэтому менять форму в одиночку нельзя.

Загрузку модели и генерацию `Translator` принимает аргументами конструктора: с подставными
функциями весь путь перевода проверяется там, где MLX не установлен.
