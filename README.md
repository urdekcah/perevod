# perevod

[![license](https://img.shields.io/badge/license-AGPL--3.0--only-0b7285)](LICENSE)
[![python](https://img.shields.io/badge/python-3.12%2B-306998)](pyproject.toml)
[![platform](https://img.shields.io/badge/platform-Apple%20Silicon-1c1c1e)](#требования)

**Русско-корейский перевод, который не ходит в сеть.** Модель лежит на диске, вычисления идут
на GPU вашего Mac. За двумя интерфейсами — командой в терминале и классом в Python — работает
один движок.

```sh
perevod translate "Здравствуйте, как дела?"
# 안녕하세요, 어떻게 지내세요?
```

---

## Требования

| Что нужно | Откуда требование |
|---|---|
| Mac на Apple Silicon, M1 и новее | Движок построен на MLX, а тот считает только на этих чипах |
| macOS 15.0 или новее | Практический минимум для MLX |
| Python 3.12 или новее | Нижняя граница из `pyproject.toml` |
| Около 5 ГБ на диске и сеть один раз | Столько весит модель; дальше она берётся из кеша |

## Установка

```sh
pip install -e .
```

## Как пользоваться

### Из терминала

```sh
perevod translate "Здравствуйте, как дела?"
```

Без аргумента или с `-` команда читает стандартный ввод и отдаёт только перевод, поэтому её
можно ставить в конвейер:

```sh
cat письмо.txt | perevod translate -
```

| Флаг | Что делает |
|---|---|
| `--model` | Берёт другой репозиторий модели |
| `--adapter-path` | Подкладывает обученный адаптер поверх базовой модели |
| `--allow-provenance-mismatch` | Разрешает адаптер от другой базы или другой формы запроса |
| `--max-tokens` | Потолок длины ответа. По умолчанию `512` |

### Из Python

```python
from perevod import Translator

translator = Translator()
print(translator.translate("Здравствуйте, как дела?"))
```

`Translator` забирает веса в память при создании — несколько гигабайт. Заведите один экземпляр
и работайте с ним: собирать новый на каждую фразу дорого.

## Подготовка данных к дообучению

Пары вы пишете вручную и складываете в `data/derived/` файлами `*.txt` — по паре на строку,
стороны через `|||`. Формат описан в `data/README.md`.

```sh
perevod prepare-data
```

Команда читает `data/derived/`, проверяет корпус целиком и до первой записи, отбрасывает
дубликаты и раскладывает остаток на `train.jsonl`, `valid.jsonl`, `test.jsonl`
и `manifest.json` в `data/splits/` — те самые имена, которых ждёт `mlx_lm.lora`.

| Флаг | Что делает |
|---|---|
| `--output-dir` | Куда писать. По умолчанию `data/splits/` |
| `--seed` | Фиксирует раскладку. По умолчанию `0` |
| `--valid-fraction`, `--test-fraction` | Доли под проверку и тест. По умолчанию `0.1` |
| `--max-length-ratio` | Граница расхождения длин; `0` снимает проверку |
| `--allow-source-conflicts` | Разрешить один исходник с разными переводами |
| `--overwrite` | Заменить свои файлы в непустом каталоге |

То же самое из Python — та же реализация, не вторая:

```python
from perevod import PrepareConfig, prepare_splits

result = prepare_splits(PrepareConfig(seed=0))
print(result.manifest["counts"])
```

Ради трёх гарантий команда и написана: ошибочная строка называется по файлу и номеру ещё
до того, как что-то записано; тот же ввод с тем же зерном даёт побайтово те же выборки;
ни одно предложение не попадает разом в обучение и в тест. Непустой `data/splits/` команда
не затирает — на этих выборках мог быть обучен адаптер.

## Дообучение

```sh
perevod train
```

Команда дообучает LoRA-адаптер на выборках из `data/splits/` и кладёт его в
`data/adapters/current/`. В каталоге с выборками обязателен `train.jsonl`; `valid.jsonl`
и `test.jsonl` необязательны, но без `valid.jsonl` обучение не покажет ошибку на проверочной
части и предупредит об этом.

Проверить данные, не запуская обучение:

```sh
perevod validate-data
```

| Флаг | Что делает |
|---|---|
| `--data` | Каталог с выборками. По умолчанию `data/splits/` |
| `--model` | Какую модель дообучать |
| `--adapter-path` | Куда положить адаптер. По умолчанию `data/adapters/<run-name>` |
| `--run-name` | Имя запуска в пути по умолчанию. По умолчанию `current` |
| `--iters` | Сколько шагов обучать |
| `--batch-size` | Размер минибатча |
| `--learning-rate` | Скорость обучения |
| `--num-layers` | Сколько слоёв дообучать; `-1` — все |
| `--max-seq-length` | Потолок длины последовательности |
| `--seed` | Зерно генератора случайных чисел |
| `--mask-prompt` | Считать ошибку только по корейской стороне |
| `--grad-checkpoint` | Менять скорость на память |
| `--overwrite` | Заменить адаптер в непустом каталоге |

Незаданный флаг не передаётся дальше вообще: в силе остаётся значение самого `mlx_lm.lora`,
а не наша догадка о нём. Ранг LoRA флагом не задаётся — на закреплённой версии обучатель
принимает его только из YAML-конфигурации.

То же самое из Python:

```python
from perevod import TrainingConfig, train_adapter

adapter_path, report = train_adapter(TrainingConfig(iterations=200, batch_size=1))
```

Перед запуском команда читает выборки целиком и отказывается стартовать, если хоть одна
строка не разбирается или собрана под другую форму запроса: иначе о несоответствии вы бы
узнали через час обучения, впустую. Непустой каталог адаптера команда не затирает — там
могут лежать часы вычислений.

Адаптер привязан к форме запроса, на которой обучался. Меняете `build_messages` или текст
инструкции — все обученные раньше адаптеры становятся негодными, и починить их нельзя,
только переобучить.

### Если не хватает памяти

Модель закреплена в 4 битах, поэтому обучение идёт как QLoRA само по себе, отдельного флага
для этого нет. Базовые веса заморожены, учатся только матрицы адаптера: постоянная часть
расхода примерно равна той же модели на переводе, а переменная растёт от длины
последовательности и размера батча.

Если запуск упирается в память или уходит в своп, ослабляйте по порядку: уменьшить
`--batch-size`, затем `--num-layers`, затем включить `--grad-checkpoint`, затем укоротить
последовательности, выкинув длинные пары из выборки.

Расхода на полном корпусе мы не измеряли. Что измерено: короткий прогон на восьми парах,
`--batch-size 1 --num-layers 4 --iters 4` — 14,7 с, 5,0 ГБ максимального резидентного
размера, 4,6 ГБ по счётчику самого обучателя, 44 токена в секунду. Пары были короткие,
поэтому цифра говорит о постоянной части расхода и почти ничего — о переменной. Единственная
внешняя точка для сравнения: Mistral-7B на M1 Max с 32 ГБ при `--batch-size 1 --num-layers 4`
даёт около 250 токенов в секунду.

Полный выигрыш от нейроускорителей M5 требует macOS 26.2 или новее.

## Перевод с адаптером

Обученный адаптер подкладывается поверх базовой модели на лету — база остаётся замороженной
и четырёхбитной, ничего не сливается и не переписывается. Это основной путь.

```sh
perevod translate --adapter-path data/adapters/current "Здравствуйте, как дела?"
PEREVOD_ADAPTER=data/adapters/current perevod translate "Здравствуйте, как дела?"
```

```python
from perevod import Translator

translator = Translator(adapter_path="data/adapters/current")
print(translator.translate("Здравствуйте, как дела?"))
```

Побеждает то, что выше: аргумент, за ним переменная `PEREVOD_ADAPTER`, за ней — никакого
адаптера. По умолчанию адаптер не подставляется никогда: его выбирают осознанно.

### Проверка происхождения

Адаптер, обученный на одной базе и подложенный под другую, не падает — он молча переводит
хуже, и списать это будет не на что. Поэтому `perevod train` кладёт рядом с весами файл
`perevod_provenance.json`: в нём записаны база, форма запроса, дата и версия обучателя.

Перед загрузкой модели файл сверяется с тем, что вы просите сейчас:

| Что в каталоге адаптера | Что произойдёт |
|---|---|
| Файла нет | Предупреждение в `stderr`, перевод продолжится |
| База и форма запроса совпали | Ничего, перевод пойдёт молча |
| База другая | Ошибка до загрузки модели |
| Форма запроса другая | Ошибка до загрузки модели |
| Файл битый или неполный | Ошибка; она не снимается флагом |

Флаг `--allow-provenance-mismatch` (в Python — `allow_provenance_mismatch=True`) превращает
две ошибки о несовпадении в предупреждения. Битый файл им не снимается: принимать там нечего,
его надо чинить.

Файл должен путешествовать вместе с адаптером. Адаптер без него получатель загрузит с одним
предупреждением вместо проверки — именно на той паре, которую проверять важнее всего.

### Слияние адаптера с базой

`mlx_lm.fuse` вплавляет адаптер в веса и отдаёт обычный каталог модели. Это удобство для
выгрузки, а не рабочий путь.

**Слияние может потерять выученное поведение.** Открытая проблема
[`ml-explore/mlx-lm#654`](https://github.com/ml-explore/mlx-lm/issues/654) описывает ровно
это, и описанный там случай — дообучение на русском, то есть то же направление, что и здесь.
Обёртки вокруг `mlx_lm.fuse` в проекте нет намеренно.

По умолчанию `mlx_lm.fuse` читает адаптеры из `adapters/` и пишет в `fused_model/`
относительно текущего каталога — то есть в корень репозитория, мимо `data/` и мимо всех
исключений при сборке пакета. Пути задавайте явно:

```sh
mlx_lm.fuse \
  --model mlx-community/gemma-4-e4b-it-4bit \
  --adapter-path data/adapters/current \
  --save-path ~/models/perevod-fused
```

Результат — обычный каталог модели, поэтому отдельного кода для него не нужно:

```sh
perevod translate --model ~/models/perevod-fused "Здравствуйте, как дела?"
```

Прежде чем такой каталог кому-то отдавать, сравните три прогона на одном и том же наборе
предложений (`perevod.probes.PROBE_SENTENCES`): голая база, база с адаптером, слитая модель.
Сначала убедитесь, что база и адаптер вообще расходятся хотя бы на половине набора — иначе
сравнение ничего не докажет. Затем прочитайте три колонки глазами. Если слитая модель
сбивается на русский или латиницу там, где адаптер давал корейский, — это тот самый дефект,
и распространять такой каталог нельзя.

Корпуса нет ни в одном из этих артефактов. Наименьших обязательств требует каталог адаптера:
он маленький, чужих весов не несёт, а базу получатель берёт сам — и проверка происхождения
ему это подтвердит.

Это не юридическая консультация.

## Выбор модели

По умолчанию берётся `mlx-community/gemma-4-e4b-it-4bit`. Сменить модель можно,
не притрагиваясь к коду:

```sh
perevod translate --model mlx-community/gemma-4-31b-it-4bit "Добрый день"
PEREVOD_MODEL=mlx-community/gemma-4-31b-it-4bit perevod translate "Добрый день"
```

Побеждает то, что выше: флаг `--model`, за ним переменная `PEREVOD_MODEL`, за ней значение
по умолчанию. Пустую переменную движок считает незаданной.

## Как устроено

Запрос к модели — диалог из двух реплик: системная ставит задачу, пользовательская несёт
исходный текст. Обе собирает `build_messages` — единственное место, где описана форма запроса.
На неё опирается и дообучение, поэтому менять форму в одиночку нельзя.

Загрузку модели и генерацию `Translator` принимает аргументами конструктора: с подставными
функциями весь путь перевода проверяется там, где MLX не установлен. Адаптер он берёт тем
же конструктором, вместе с базой: пути, на котором адаптер попал бы в модель, не зная, к
какой базе он приложен, в коде просто нет.
